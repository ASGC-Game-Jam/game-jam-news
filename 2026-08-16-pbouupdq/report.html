Server report: Aug 09 – Aug 16, 2026

Pods take shape, TDD/TDS lands, and Narrative wrestles with how 'cozy' Atlantis should be

1956 messages · 143 active members · 75 active channels

It was a busy week (Aug 9–16) of 1,956 messages from 143 members as the ASGC Game Jam 2026 (Project Atlantis) heads from Sprint 2 into Sprint 3. Most of the work was structural. Swart Tigerhorn (Andre) paused TDD creation on Aug 11, and after long debates with VibeBlind (Seth), Matt Barnes and dbugslayer about how heavy the process should be, he released a new TDD/TDS template on Aug 13: one TDD per FDS, split into actionable TDS docs that feed GitHub Projects tickets. The lighter mini template became the default 'TDD', and the larger one was renamed 'Expanded TDD'. VibeBlind set up parent tickets across the feature pods (Oxygen, Combat, Stealth, Investigation, Dialogue, Traversal) and asked each pod to break features into smaller chunks. Production audited Point-of-Contact gaps, Cafedunoir launched a weekly team Demo starting Friday Aug 14, and shadowarrior is covering production/EP questions while Lori travels until Aug 23.

Narrative was the loudest corner of the server. The Aug 9 narrative voice meeting and follow-up threads reworked the premise. The 'eldritch god' became a wondrous or exploited sea creature the player can befriend. The Bleaching disease was reframed around stress and burnout, with quests that relieve NPC stress as a cozy hook. Combat could 'cleanse' bleached NPCs instead of knocking them out, an idea the Combat pod embraced. That sparked a real debate over whether the disease should stay at all. Charlotte/Duncan warned that dropping it would undo character bios, and Kyu proposed a middle ground. The decision is set for the Sunday Aug 16 ND Leads Meeting, which is open to the whole department. Audio and Narrative also aligned on voice: only a 1–2 sentence intro Narrator will be recorded, and everything else will be gabble, designed VO/SFX or synth. Narrative director Oldladies7 announced a gradual step-back for a full-time job and drew a warm send-off.

On the craft side, Art wrapped up Sprint 2 concepts (MC, NPCs, props, city square) with detailed, well-received feedback from Zef. sevenn4 iterated on underwater bubble and caustics VFX, and a new Water tech-art pod launched with sevenn4 as owner. Clara got Tech Audio fully set up: a Git onboarding guide, the audio folder merged into main, GitHub issues for audio tasks, and a ClickUp–GitHub integration. Meanwhile, Hailey's sync notes laid out a three-layer dynamic music system. Tech fixed Gitea LFS auth (use a personal access token, not your password), published the Git Hygiene doc, tested the manual Steam build pipeline end to end, and added an in-game build version for QA.

Hello everyone @Design

We have a new template for the TDD! 🎉 As a matter of fact there are 2 documents now. We have decided to subdivide each TDD into many TDS.

As a reminder, TDD and TDS should be written following the guidelines and conventions defined on our main Tech Design Wiki Page

Now, for a quick F.A.Q.

  • What is a TDD? The TDD translates that feature (FDS) into technical terms. It identifies the required system behavior, divides the work into small implementable technical outcomes (many TDS), and defines how those outcomes must interact. It won't contain any implementation details. (More Details and Document List)

  • Then what is a TDS? The TDS contains the implementation instructions for one of the TDD actionable items. It defines which pieces to use, the assets involved, implementation flow, required handoffs, and acceptance criteria. (More Details and Document List)

  • I am Tech and I was assigned to implement a feature! Good, your task should have a link to the TDS that contains the instructions for the implementation. Every TDS is a Google Docs Tab inside its parent TDD, so if you need any higher level information from the TDD it will be easily accessible as well.

About Gitea

GitHub is the front door for this project: issues, branches, PRs, code review all happen there. Gitea runs underneath as the Git LFS credential and lock server, it is not a separate place you push code to.

You will touch Gitea in two situations: - First clone or pull, if Git prompts for LFS credentials - Locking shared binary assets before editing them, so two people are not fighting over the same .uasset file To set it up: 1. Settings->Applications -> New Token You will need to give it a name and then in all of the little check sphere set them to Read/Write
